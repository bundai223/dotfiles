# ドキュメント

このディレクトリには、リポジトリの運用手順と設計上の判断を記録します。

## ADRの運用

今後、保守方法、構成、依存関係、互換性方針など、継続的な作業に影響する
重要な技術判断は `docs/ADR/` にArchitecture Decision Record (ADR)として
記録します。

ADRは次のルールで運用します。

1. ファイル名は `NNNN-short-title.md` とし、4桁の連番を付けます。
2. `ステータス`、`日付`、`背景`、`決定`、`影響` を記載します。
3. ステータスには `Proposed`、`Accepted`、`Deprecated`、`Superseded` のいずれかを
   使用します。
4. 判断が確定する前は `Proposed`、運用を開始するときは `Accepted` とします。
5. AcceptedになったADRの判断内容は、誤字修正や参照追加を除いて書き換えません。
6. 方針を変更するときは新しいADRを追加し、古いADRを `Superseded` にして
   新しいADRへのリンクを記載します。
7. ADRに基づく手順書やコードから、対応するADRへリンクします。

軽微な実装詳細、一時的な調査結果、既存方針の範囲内にある変更はADRの対象外です。
判断が複数の将来の変更に影響するか、後から理由を知る必要があるかを記録の基準に
します。
