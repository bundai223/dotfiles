# Neovimメンテナンス

プラグインの検証方針は
[ADR 0001](ADR/0001-test-lazy-loaded-neovim-plugins-in-two-layers.md)で定義します。

この文書では、診断、プラグイン更新、設定移行を一つの変更に混在させずに、
このリポジトリのNeovim設定を保守する手順を定義します。

## 現在の構成

- `config/nvim/init.vim` が設定のエントリーポイントです。
- `config/.config/nvim/lua/plugins.lua` にlazy.nvimのプラグイン定義があります。
- `config/.config/nvim/lua/plugin_config/` にプラグイン固有の設定があります。
- `~/.config/nvim/init.vim` からリポジトリの `config/nvim/init.vim` を読み込みます。
- `~/.config/nvim/lua` は `config/.config/nvim/lua` へのシンボリックリンクです。

最終的には `lazy-lock.json` を `config/.config/nvim/lazy-lock.json` に配置し、
`~/.config/nvim/lazy-lock.json` へリンクするか、ほかの方法で配置します。この移行が
完了するまではプラグインのバージョンが端末内にしか存在せず、リポジトリから再現できません。

## 通常の手順

1. 作業ツリーがクリーンな状態で `bin/nvim-maintenance-check` を実行します。
2. 生成されたレポートのパスをIssueまたはメンテナンス記録へ残します。
3. `:checkhealth` の警告より先に起動エラーを修正します。
4. 一つの変更では、一つのプラグインまたは関連するプラグイングループだけを扱います。
5. 診断を再実行し、変更前後のレポートを比較します。
6. 影響を受ける操作をNeovim上で対話的に確認します。
7. 設定変更と、それによって生じたロックファイルの変更を一緒にコミットします。

最初の診断として `:Lazy update` を実行してはいけません。既存の障害を先に記録し、
その後 `:Lazy update <plugin>` で対象を限定して更新します。全体更新は、起動が正常で
ロックファイルが追跡されている状態になってから実施します。

## 検証レベル

- 起動: `bin/nvim-maintenance-check` が正常終了することを確認します。
- ヘルスチェック: レポート内の `ERROR` と `WARNING` を確認します。
- 全プラグイン: 管理対象を明示的にロードし、ロードエラーを収集します。
- 遅延ロードシナリオ: 事前ロードせず、代表的なイベント、FileType、コマンド、
  キーマップを契機にロードさせます。
- プラグイン挙動: 代表的なファイルを開き、変更対象の機能を確認します。
- 言語ツール: 日常的に使用する各言語で `:LspInfo`、フォーマット、診断、補完を
  確認します。

診断ではNeovimのキャッシュと状態をシステムの一時ディレクトリへ分離します。
通常の設定とインストール済みプラグインを使用しますが、プラグイン更新や
`lazy-lock.json` の変更は意図的には行いません。

制限環境で実行した場合、通常のNeovimデータディレクトリへの書き込み確認や、
providerのネットワーク確認が失敗することがあります。これらは環境由来のノイズとして
区別し、起動の終了コードと設定のスタックトレースを主要な判断材料にします。

## 更新順序

障害の原因を特定しやすくするため、次の順序で更新します。

1. Neovim本体との互換性と非推奨API
2. lazy.nvimと起動時に必要なUIプラグイン
3. Treesitter
4. LSP、Mason、補完、スニペット、フォーマッター
5. ナビゲーション、Git、編集支援、任意プラグイン
6. 開発停止または未使用のプラグインと古い設定モジュールの削除

基準となる状態が正常になった後は、毎月およびNeovimのマイナーバージョン更新後に
このメンテナンスを実行します。
