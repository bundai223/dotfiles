# 2026-07-24 LLM Wiki運用スキル設計

## 背景

LLM Wikiの運用に使用する自作スキルとして、セッション開始時の読み込みを担当する
`load-wiki-as-context` と、作業の区切り・push前の記録と蒸留を担当する
`update-wiki` を後で実装することになった。

本記録では、既存の `wiki/SCHEMA.md` から想定される両スキルの責務と処理を整理する。

## `load-wiki-as-context` の設計案

LLM Wikiから現在の作業に必要な情報だけを読み込む、読み取り専用スキルとする。

想定する処理:

1. Gitリポジトリのルートを特定する
2. `wiki/SCHEMA.md` の存在を確認して読み込む
3. `wiki/index.md` を読む
4. ユーザーの依頼、変更対象ファイル、現在のタスクから関連ジャンルを推定する
5. 関連ジャンルの `index.md` を読む
6. 必要なWikiページだけを読む
7. 根拠の確認が必要な場合だけ、ページの `sources` にある `raw/` を読む
8. 読み込んだ知識、未解決事項、参照ファイルを簡潔に報告する

想定する制約:

- ファイルを変更しない
- 全Wikiページを一括で読まない
- `deprecated` のページは原則として現行知識に採用しない
- `needs-review`、未解決の矛盾、低い `confidence` を明示する
- 関連情報がWikiにない場合は、そのことを明示して通常の調査へ進む

## `update-wiki` の設計案

作業中に得た情報を `raw/` に記録し、再利用できる知識を `wiki/pages/` に蒸留する
書き込みスキルとする。

想定する処理:

1. 今回の会話、変更差分、検証結果、決定事項を確認する
2. 将来も有用な新しい情報があるか判断し、なければ変更せず終了する
3. 新しい情報を適切な `raw/` ファイルへ記録する
4. 既存Wikiページとの重複、関連、矛盾を検索する
5. `Create`、`Update`、`Split`、`Synthesis` の操作を選ぶ
6. Wikiページを作成または更新する
7. ジャンルの `index.md` と `log.md` を更新する
8. ページ数が変わった場合は `wiki/index.md` を更新する
9. sources、リンク、ページ数、frontmatterを検証する
10. 更新内容と、更新しなかった情報を報告する

情報の振り分け:

| 情報 | 記録先 |
|---|---|
| 作業セッション、調査、検証結果 | `raw/conversations/` |
| ユーザーが確定した判断 | `raw/decisions/` |
| 障害や再現手順 | `raw/issues/` |
| 再利用できる結論、手順、パターン | `wiki/pages/` |
| 複数回にまたがる未完了作業 | `docs/tasks/` |
| 継続的に影響する重要な技術判断 | `docs/ADR/` |

想定する安全策:

- 既存の `raw/` を編集または削除しない
- 訂正は新しいraw記録として追加する
- 秘密情報、個人情報、トークンをrawへ保存しない
- Wikiの主張には存在する `sources` を必ず付ける
- rawにない推測を確定事項としてWikiへ書かない
- 矛盾時は自動上書きせず、`needs-review` と「未解決の矛盾」節を使用する
- コミットやpushを自動で行わない
- 一時的な実装詳細や単なる作業ログを無条件にWiki化しない

## 実装順序

最初は次の最小機能を実装する。

- `load-wiki-as-context`
  - `SCHEMA → index → 関連ジャンル → 必要ページ` の読み込み
  - 読み込んだページ一覧と要点の報告
- `update-wiki`
  - `raw/conversations/` への新規記録
  - 既存ページの検索
  - `Create` または `Update`
  - `index.md`、`log.md`、sourcesの整合性確認

`Split`、`Synthesis`、矛盾処理の高度化は後続の改善対象とする。誤った知識の長期保存を
避けるため、`update-wiki` は当初、判断の自由度を低くして人間が確認しやすい出力にする。
