# 2026-07-28 Neovimエラー復旧（セッション記録）

## 発生していたメッセージ

- `E348: No string under cursor`
- `[cmp-dictionary] You need to check :h cmp-dictionary-option-document`
- `vim.lsp.buf_get_clients() is deprecated`

## 診断結果

- Neovim `0.12.4` のヘッドレス起動と `:checkhealth` は終了コード `0` だった。
- `cmp-dictionary` の警告は、`document` オプションがbooleanからtableへ変更された後も
  `document = true` が残っていたことが原因だった。
- LSP APIの非推奨警告は、`symbols-outline.nvim` と `nlsp-settings.nvim` の双方で再現した。
- `E348` は `*` と `#` に独自マッピングが存在しない状態でも、カーソル下に検索対象の
  文字列がないときにNeovim本体が出すメッセージだった。

## 実施内容

- 使用していない `cmp-dictionary` のdocumentオプションを削除した。
- 更新が止まっている `symbols-outline.nvim` を後継の `outline.nvim` へ移行した。
- `nlsp-settings.nvim` を削除し、JSON schemaは既存のSchemaStoreカタログと
  リポジトリ固有schemaから構成するようにした。
- `outline.nvim` をインストールし、通常起動、`Outline` コマンド、
  `cmp-dictionary` のロードで該当警告が出ないことをヘッドレスで確認した。

## 未解決事項

- `lazy-lock.json` はまだ `~/.config/nvim/` にあり、リポジトリ管理へ移行していない。
- `E348` の表示自体はNeovim本体の標準動作であり、抑制していない。
- 遅延ロードを含む全プラグインの自動テストは未実装。

## 追加で発生したmason-lspconfigエラー

`:Notifications` で、`mason-lspconfig.nvim` の設定ロード時に
`setup_handlers` が存在しないエラーを確認した。インストール済みの
`mason-lspconfig.nvim 2.2.0` ではhandler方式が廃止され、Neovim組み込みの
`vim.lsp.config()` と `vim.lsp.enable()` を使う方式へ変わっていた。

次の対応を行った。

- 全LSP共通のcapabilitiesと`on_attach`を `vim.lsp.config("*", ...)` へ移行
- JSON、Terraform、YAML、Volar、Luaの個別設定を `vim.lsp.config()` へ移行
- `mason-lspconfig` の自動有効化を利用
- 更新が止まっている `rust-tools.nvim` を削除し、`rust_analyzer` を標準設定へ戻した
- Luaファイルを開いて `BufReadPre` を発火させ、設定ロードエラーが出ないことを確認

## Notificationsコマンドの回帰

`nvim-notify` の遅延ロード条件が `BufReadPre` だけだったため、ファイルを開く前は
`:Notifications` が存在しなかった。`Notifications` と `NotificationsClear` を
コマンドによる遅延ロード条件へ追加した。

最初のヘッドレス検証では終了コードが `0` だったが、通常画面で起動直後に実行すると
lazy.nvimから `Command Notifications not found after loading nvim-notify` が表示された。
`nvim-notify` は `require("notify")` だけではコマンドを登録せず、`setup()` の実行時に
登録する実装だった。コメントアウトされていた `notify.setup({})` を有効化し、通常画面の
起動直後に `:Notifications` を実行してエラーが出ないことを確認した。
